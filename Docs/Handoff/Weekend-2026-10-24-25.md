## 현재 Scene·GPU 데이터 구조

```text
Scene
 └─ GameObject: ObjectId, root Transform
     ├─ ModelInstance: 공유 원본 Model + CPU 애니메이션/node/joint pose
     ├─ MeshComponent A: ComponentId, TRS, GeometryRevision, PosedGeometry
     ├─ MeshComponent B: ComponentId, TRS, GeometryRevision, PosedGeometry
     └─ ColliderComponent 참조들: Id, MeshId, GeometryRevisionId, QueryHandle
```

- ComponentId는 owner 안에서 발급하고 재사용하지 않는다. 서로 다른 owner에서 같은 값이 나올 수 있으므로 외부 키는 `(ObjectId, MeshId)`다.
- `Attached`: `Wc = owner * component`. `WorldIndependent`: 컴포넌트 TRS가 월드 변환이다. 현재 A/B는 별도 Transform 저장 공간을 갖지만 절단 직후 같은 값을 복사하므로 붙어 보인다. 각 조각의 중심으로 원점을 자동 이동시키는 구현은 아니다.
- 원본 GPU Model 버퍼 → CPU node/bone matrices → PreparePoseCS → 컴포넌트별 RAW40 pose → VS에서 Wc/VP 적용 순서다. CPU 애니메이션 평가와 GPU 정점 스키닝을 구분한다.
- Static cutter는 **현재 revision**의 Data/IB/Pose를 읽고 A/B canonical local geometry를 만든다. 재절단은 기존 cap을 포함한 최신 결과를 입력으로 쓰며 원본 Model로 돌아가지 않는다.
- GeometryRevision은 생성 GPU 자원·재질·bounds·parent provenance와 원본/부모 strong refs를 유지한다. 생성 geometry에는 node/skin/source-frame 변환을 다시 적용하지 않는다.
- 정상 경로는 전체 정점을 CPU로 매 프레임 읽지 않는다. 검증용 snapshot/readback은 `-cut-validate 1`에서만 추가된다. GPU 자원 지연 해제 큐는 아직 없고 일부 교체/삭제에서 전역 GPU 대기가 남아 있다.

GPU 관련 핵심 파일은 `Model/{GeometryBuffers,GeometryRevision,PosedGeometry}.*`, `MeshCutting/GPU/{GpuMeshCutter,CutTypes}.*`, `MeshCutting/Shaders/`, `MeshCutting/tests/GpuCutValidation.cpp`, `ModelViewer/Scene/{MeshComponent,CuttingSystem}.*`다.

## GPU 절단에서 해결한 문제와 남은 제한

- 접촉·공면에서 cap-only 조각을 만들던 문제를 차단했다. 양쪽 비퇴화·비공면 surface와 활성 경계가 있어야 split이며 새 cap을 제외한 surface count도 검사한다.
- 평면 위 기존 모서리는 segment-local hash에서 양/음 표면 지지를 확인한다. 전역 원본 인접성 표를 만들지 않는다.
- 유한 사각형이 전체 절단 경계를 덮지 못하면 후보 전체를 거절한다. 사각형 내부만 부분 절개하는 기능은 없다.
- 열린 Bunny에서는 열린 경계의 cap만 생략한다. 독립 닫힌 loop는 채우지만 outer/hole hierarchy Boolean은 없다. 모든 임의 입력의 수밀성을 보장하지 않는다.
- 새 B를 매번 월드 법선 방향으로 0.6 이동시키던 진단 동작이 반복 절단 외관 차이를 만들었다. 기본을 `-cut-gap 0`으로 바꿨다. `-cut-gap 0.6`은 실제 Transform을 바꾸므로 후속 절단 위치에도 영향을 준다.
- 출력 side당 최대 1M vertices, branch retained 예상량 512 MiB, generation 32 제한이 있다. 전체 Scene 메모리 예산은 아니다. cap 관련 별도 용량/라운드 제한은 구현 문서를 참조한다.
- GPU Skeletal 절단은 아직 거절된다. 열린 렌더 메시의 signed triangle integral을 물리적 부피로 해석하지 않는다.

## Jolt 조회 구현 (`39db69f3`에 커밋)

선정 SDK는 **Jolt v5.6.0**, commit `e77f175595e64cb44218cc9d9d56fc365ad0e36a`다. PhysX와의 속도·메모리 우열을 측정해 선정한 것이 아니라 CPU 물리 결합의 단순함과 현재 요구 충족을 우선했다. GPU 렌더 절단은 유지한다.

### 빌드와 새 파일

- `Tools/BuildJolt.ps1`: archive 다운로드·SHA256 검증·CMake 증분 빌드·테스트. Windows PowerShell에서도 동작하도록 .NET SHA256 계산을 사용한다.
- `MiniEngine/Physics/CMakeLists.txt`: 공식 Jolt target과 MiniPhysics adapter. 정적 lib, v143/x64, C++17, Debug `/MDd`, Release `/MD`, SSE2. Jolt Compute backend는 OFF다.
- `MiniEngine/Physics/Physics.vcxproj/.filters`: 기존 `.slnx`에 연결하는 NMake bridge. 엔진 전체를 CMake로 전환하지 않는다. Profile은 SDK Release를 링크한다. ARM64 연결은 아직 지원하지 않는다.
- `MiniEngine/PropertySheets/Physics.props`: 최종 MiniPhysics.lib/Jolt.lib 링크 경로.
- `MiniEngine/Physics/ThirdParty.md`: 고정 버전·hash·MIT 고지.
- SDK source/build는 ignored `MiniEngine/Build/ThirdParty/Jolt/` 아래에 있으며 커밋 대상이 아니다. 첫 준비에는 공식 소스 다운로드가 필요하다. archive SHA256은 `1f32328fb763135de10a244568d6ccb2ed9b1e6593fafe6dc6db5b2719d330bd`다.

### 현재 API와 실행 흐름

`MiniEngine/Physics/PhysicsWorld.h/.cpp`는 SDK 수명과 조회 body를 소유한다. `Initialize`, `CreateQueryBox`, `UpdateQueryBox`, `RemoveCollider`, `QueryAabb`, `Clear`, `Shutdown`을 제공한다. 공개 handle은 단조 증가 uint64이고 Clear/재초기화 후에도 재사용하지 않는다. SDK의 BodyID를 Scene에 노출하지 않는다.

`ModelViewer/Scene/PhysicsSystem.h/.cpp`는 Scene ID와 SDK handle을 연결한다. `SyncColliders`는 준비된 Static 메시의 기존 보수적 월드 구를 감싸는 Box를 자동 등록·갱신·삭제한다. `QueryCutCandidates(plane)`는 다음을 처리한다.

1. 유한 사각형 월드 AABB를 epsilon/ULP만큼 보수적으로 확장해 Jolt broadphase를 조회한다.
2. broadphase의 이동 전 여유 영역 후보를 현재 body AABB로 다시 거른다.
3. 기존 평면/경계 구 조건을 유지하고 현재 ID/revision/StateVersion/Wc를 검사한다.
4. owner+mesh 단위로 정렬·중복 제거한 `CutCandidate` snapshot을 반환한다.

조회 Box는 **실제 동적 충돌체나 질량 계산용 proxy가 아니다.** 기본 예산은 4096이며 용량 부족·SDK 비활성·SDK 지원 범위 밖 경계는 기존 검사 fallback으로 유지한다. query filter와 simulation pair filter는 분리했고 조회 body 사이의 접촉 반응은 없다. fixed step·중력·job pool·속도 전달은 아직 없다.

현재 `CuttingSystem::RequestAll`은 이 API 한 번으로 후보 큐를 만든다. `ModelViewer::Update`에서 완료된 절단 게시 → 입력 처리 → Scene.Update/GraphicsContext.Finish → SyncColliders → SubmitPending/새 Request 순서다. 생성 B는 같은 batch에 재삽입하지 않는다. 종료는 Cutting.Clear → Physics.Clear → Scene.Clear → renderer 종료다.

`SyncColliders`는 여전히 매 프레임 적격 메시를 순회한다. Box는 경계가 변할 때만 교체하며 정상 query는 hit와 fallback 목록만 읽는다. 대규모 성능 향상이나 전체 프레임 순회 제거를 주장하지 않는다.

## Unreal 조사와 확정한 방향

직접 읽은 코드는 UE5.3.2 공개 GitHub 미러의 Epic 작성 소스다. 최신 Epic 비공개 저장소나 Unreal 실행 검증으로 보고하지 않는다. 상세 링크는 UnrealSourceComparison 7절에 있다.

- ProceduralMeshComponent 자체가 렌더 데이터와 별도 convex 충돌 데이터를 가진다. Box/CapsuleComponent를 반드시 외부에 붙이는 구조가 아니다.
- SliceProceduralMesh는 기존 convex도 자르고 B를 같은 owner의 새 컴포넌트로 만든다. 새 Actor를 만들지 않는다. 같은 owner와 transform attachment는 다른 관계다.
- 그 함수는 새 B의 simulation 활성화나 부모 속도 전달까지 처리하지 않는다. 관찰한 코드를 질량/운동량 보존 보장으로 확대하지 않는다.
- SkeletalMeshComponent는 Physics Asset을 바탕으로 내부 Bodies/Constraints 배열을 관리한다. 본마다 별도 BoxComponent를 생성하지 않으며 모든 bone에 body가 필요한 것도 아니다.
- BreakConstraint는 관절을 끊고 자식 body들을 물리로 전환하지만 피부 삼각형/cap을 생성하지 않는다. 물리 분리와 시각 절단은 별도 책임이다.
- 사용자는 같은 GameObject 아래 다중 MeshComponent를 유지하는 방향을 채택했다. 개별 조각 기즈모 편집은 아직 없고 후속 선택·기즈모·Undo 확장이 필요하다.

```powershell
../Build/x64/Debug/Output/ModelViewer/ModelViewer.exe -debug 1 -model Models/cube.glb -physics-query-self-test 1 -physics-query-checks 1 -physics-query-exit 12 -cut 4 -cut-scene 1 -cut-repeat-plane 1 -cut-step-y .25 -cut-validate 1 -cut-expect-publications 4 -cut-gap 0
```

`-physics-query 0`은 SDK 조회 OFF, `-physics-query-capacity 1`은 fallback 강제, `-physics-query-self-test 1`은 임시 객체로 장면 통합 검사, `-physics-query-checks 1`은 기존 전수 검사와 후보 대조, `-physics-query-exit N`은 N프레임 이후 자동 절단 완료를 기다려 정상 종료다. 일반 실행은 자동 종료하지 않는다.

- `참고문헌/` PDF 8개 삭제
- untracked `.claude/` 로컬 설정

Jolt 구현과 관련 문서·새 테스트만 별도로 검토한다. 생성 lib/exe·SDK source/cache·compiled shaders·IDE 설정은 제외한다. 저장소 전체 `git add .`를 하지 않는다. 이 세션은 Jolt 변경을 커밋·푸시하지 않았다.

## 다음 작업자가 특히 주의할 설계 문제

> Static 조각 물리의 현행 요구사항과 구현 순서는 [StaticPiecePhysics.md](../Physics/StaticPiecePhysics.md)를 따른다. 아래 속도 전달·바닥+Box 우선 지시는 이전 계획이며, 움직이는 조각 절단과 속도 전달은 현 범위 밖이다.

1. **동적 조각을 자르려면 취소 세대부터 분리해야 한다.** 현재 SetTransform은 매 호출 StateVersion을 증가시키며 GPU 완료는 Wc/StateVersion 변경을 취소한다. 물리를 그대로 연결하면 지연 절단이 계속 취소될 수 있다. physics rigid pose와 사용자 편집/geometry 세대를 구분해야 한다.
2. **조회 Box를 낙하용으로 재사용하지 않는다.** Cube 원본에 대한 닫힌 실제 proxy부터 준비하고, proxy의 질량·COM·관성 및 원본 node/source frame/scale 대응을 검증해야 한다.
3. **body 원점과 COM을 구분한다.** Jolt GetPositionAndRotation은 생성 원점 기준, GetCenterOfMassPosition은 속도 전달용 COM 기준이다. 자동 recentering과 수동 보정을 중복 적용하지 않는다. owner 비균일 scale×component rotation이 만든 전단을 조용히 버리지 않는다.
4. **GPU A/B와 collider A/B는 함께 게시한다.** 현재 SetGeometry/B 추가는 할당을 포함한다. 결과·새 body·컨테이너 등을 먼저 준비하고 revision 재검사 후 안전한 경계에서 교체해야 한다. 한쪽 cook 실패/삭제/stale에서 부모를 유지한다.
5. **동적 절단 시 최신 속도를 전달한다.** `v_child = v_parent + omega × (COM_child − COM_parent)`를 사용하고 질량 합·동일 기준점의 관성/운동량을 검사한다. 열린 Bunny 적분을 질량으로 쓰지 않는다.
6. **Skeletal은 마지막에 확장한다.** 본별 body·constraints·animation/physics pose blend·관절 분리와 GPU skeletal patch 절단을 각각 작은 단계로 분리한다. side당 body 하나와 연결 island별 body 분리도 구분한다.

조회 구현은 2026-10-26 리뷰 후 `39db69f3`에 커밋됐다. 새 구현 지시를 받으면 fixed60Hz 바닥+Box 낙하부터 진행하는 것이 다음 검증 가능한 범위다. 이번 인수인계 요청만으로 추가 simulation 구현을 시작하지 않았다.

AGENTS의 약300줄/한 개념 리뷰 원칙, 새/수정 함수 위 한글 역할 주석, Debug/Release 검증을 따른다. 사용자는 이번 조회 작업에 대해 단계별 자체 리뷰 후 완료까지 진행하도록 허용했지만 이를 모든 후속 작업의 무제한 실행 지시로 확대하지 않는다. Geometry를 수정하면 CPU 검증이 필요하다. AGENTS의 PlaneSlicerTests.cpp는 현 checkout에 없으며 실제 CutPlaneTests.cpp와 관련 새 테스트를 기준으로 누락 지침을 정리해야 한다. 동시에 작업할 때 코드 작성 세션은 하나로 유지한다.
