## 추출 GPU 시간 (µs)
`SkeletalPatchJob::Submit`의 모든 현존 dispatch를 직접 D3D12 timestamp로 감쌌다. 각 Mode 시작 timestamp 직전에 barrier를 flush하며 barrier는 Mode 시간 밖이다([PF-2](PatchPrefixScan.md) 2절·7절 항목 7).
`ScopedTimer`는 사용하지 않았다. 기존 비동기 제출을 유지하고 완료 fence를 확인한 후 query readback을 읽는다. 상태가 있는 재절단도 Mode 0/1/6/7/2를 사용한다.
전체는 추출 context 시작부터 출처·카운터 복사와 최종 상태 전환까지다. gap=전체−Mode 합으로, barrier·바인딩·dispatch 사이 간격·복사와 임시 query resolve 비용을 포함한다. 순수 barrier 시간으로 해석하지 않는다. `avg`는 같은 요청 위치의 3회 산술평균이며 재절단 요청 2만 HasState=1이다.

## 미검증·해석 한계와 원복
- cap 생성 GPU 시간은 미측정: 여러 cutter 단계에 걸친 생성·연결·삼각분할 구간을 별도로 정의해야 하므로 이번 작은 임시 계측에서 생략했다.
- Influence Mode 3/4도 계측 코드는 있으나 지정 실행에서 미실행이다. 제거된 Mode 5/8은 현행 dispatch가 없다. GPU clock·온도·전원·백그라운드 부하를 통제하지 않았다.
- CPU 구간에는 기존 동기 readback과 첫 요청 초기화, debug-output 수집이 포함된다. query 삽입 전의 완전 비계측 실행 시간과의 차이는 측정하지 않았다.
- GPU palette용 프레임 upload allocator·descriptor heap·드라이버 오버헤드·CPU 전체 heap·전체 상주 revision chain·정확한 peak 메모리는 미측정이다. palette의 capacity는 CPU vector 저장 용량이며 GPU allocation 값이 아니다.
- cutter 자체의 전체 scratch와 압축 입력 A/B를 보존하는 전체 메모리는 미집계다. 위 표는 추출 job·원본 mask·분류/압축의 직접 버퍼·게시 조각 자원의 기준이다.
