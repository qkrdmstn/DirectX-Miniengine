# 참고자료

최초 확인: 2026-10-23. 단일 단면 관점 재확인: 2026-10-25.

현재 조사 범위는 평면 절단과 GPU 단면 삼각분할이다. 기존 자유곡선 기반 절단 접근은 채택하지 않는다.
아래 문헌은 알고리즘 참고 자료이며, 현재 프로젝트의 GPU 절단 구현이나 성능 검증 결과가 아니다.

## 1. GPU에서 다각형들을 병렬 삼각분할

**Shadi Alawneh, Dennis Peters, “2D Triangulation of Polygons on CUDA.”**

- 발표: IEEE HPCS 2013, pp. 497–503.
- DOI: [10.1109/HPCSim.2013.6641459](https://doi.org/10.1109/HPCSim.2013.6641459).
- 원문: [저자기관 PDF](https://www.engr.mun.ca/~dpeters/papers/AlawnehPeters13a_hpcs2013.pdf).
- 확인 근거: 논문 원문.

CUDA kernel에서 다각형마다 스레드 하나를 배정한다. 각 스레드 내부에서는 ear를 하나씩 찾아 제거한다.
즉 여러 다각형 사이의 병렬화이며, 단일 다각형 내부의 여러 ear를 동시에 제거하는 구현은 아니다.
입력은 simple 2D polygon이고, hole 처리 지원은 이번 원문 확인에서 검증하지 못했다.

여러 절단면을 동시에 처리하거나, 삼각분할 결과를 CPU로 가져오지 않고 GPU에 유지하는 흐름의 참고 자료다.
단일 작은 절단면의 GPU 가속 효과를 입증하는 자료로 해석하지 않는다.

## 2. 한 다각형 내부의 ear 제거 병렬화

**Günther Eder, Martin Held, Peter Palfrader, “Parallelized ear clipping for the triangulation and constrained Delaunay triangulation of polygons.”**

- 게재: Computational Geometry 73 (2018), pp. 15–23.
- DOI: [10.1016/j.comgeo.2018.01.004](https://doi.org/10.1016/j.comgeo.2018.01.004).
- 서지·초록: [출판사 페이지](https://www.sciencedirect.com/science/article/pii/S092577211830004X).
- 확인 근거: 출판사 서지와 저자 공개 논문 원문.

Divide-and-conquer, partition-and-cut, mark-and-cut의 세 병렬화 방법을 다룬다.
독립적으로 제거할 수 있는 ear들을 선택해 한 다각형 안의 작업을 병렬화한다.
단, 구현과 실험은 CPU/OpenMP이며 GPU 구현 논문은 아니다.
Hole이 있는 입력에는 bridge를 삽입해 simple polygon 형태로 만드는 전처리를 사용한다.

단일 단면의 ear 제거를 병렬화하는 알고리즘 참고 자료다. CUDA나 HLSL 이식, GPU상의 동기화와
출력 관리가 검증되었다는 의미는 아니다. 작은 단면에서도 더 빠르다고 가정하지 않는다.

## 적용 범위 구분

| 항목 | CUDA 논문 (2013) | 병렬 ear clipping 논문 (2018) |
| --- | --- | --- |
| 실행 환경 | CUDA GPU | CPU/OpenMP |
| 병렬화 단위 | 여러 다각형 | 한 다각형 내부의 작업 |
| Hole 처리 | 지원 확인 못함 | Bridge 전처리 |
| 프로젝트에서 참고할 부분 | GPU에서 삼각분할 결과 유지 | 독립 ear 선택·분할 전략 |

두 문헌만으로 GPU 단면 생성 전체가 해결되지는 않는다. Ear clipping 이전의 절단 선분 연결,
폐곡선 구성, hole 판정과 이후의 렌더 출력 처리는 별도로 검토해야 한다.


## 3. 단일 단면 내부 병렬화 분석

이번 목적은 여러 polygon의 처리량이 아니라 하나의 cap 영역을 완성하는 지연시간이다. 근거는 위 두 원문과 [2018 저자 공개 PDF](https://geder.at/static/research/2018/2018%20Eder,%20Held,%20Palfrader%20-%20Parallelized%20ear%20clipping%20for%20the%20triangulation%20and%20constrained%20Delaunay%20triangulation%20of%20polygons,%20CG%202018%20%5BEdeHP18a%5D.pdf)다. 논문 요약과 아래 프로젝트 제안을 구분한다.

### 원문에서 확인한 범위

2013 논문 II-B/II-C는 polygon 하나를 thread 하나가 순차 처리한다. 단일 cap 내부 병렬 가속 근거로 쓰지 않는다. 2018 논문 §2는 한 polygon의 공간 분할(Divide-and-conquer), 경계 chain 분할(Partition-and-cut), 교대 후보 처리(Mark-and-cut)를 제시한다. 공간 분할에는 Steiner point 복구, 경계 분할에는 잔여 순차 처리가 있다. Mark-and-cut은 후보 표시 후 병렬 ear 제거와 잔여 순차 처리를 반복한다. 임의의 ear 전부를 동시에 제거하는 방식이 아니다.

2018 §3의 구현은 CPU/OpenMP이고 hole bridge 전처리도 CPU 순차다. 실험의 병렬 이득은 경계 정점 약 15,000개 이상에서 나타났으며 GPU 임계값이 아니다. 전체 원본 메시 정점 수와 단면 경계 정점 수를 혼동하지 않는다. GPU/HLSL, 작은 cap 지연시간, 절단선 연결까지의 가속은 두 자료에서 검증되지 않았다.

### 우리 GPU 경로에 대한 해석·검증안 (논문의 구현 결과 아님)

```text
한 번의 절단에서 나온 선분
  -> 단면 평면의 2D 점/선분
  -> 끝점 연결·loop 정렬·hole/영역 판별
  -> 한 영역 내부의 ear 후보 검사와 제거 라운드
  -> cap 정점/인덱스 출력
```

하나의 단면에도 외곽과 구멍이 있을 수 있다. loop 간 병렬 처리만으로 목적을 달성했다고 보지 않고, 하나의 경계 내부 작업을 비교한다. 이 논문들은 선분 연결·영역 분류를 해결하는 전체 절단 시스템이 아니다.

- 첫 검증 대상은 Mark-and-cut에서 동기를 얻은 **라운드 방식 GPU 변형**이다. 공간 분할에서 생기는 추가 교차점/복구 작업을 처음부터 요구하지 않는 점이 장점이며, 성능 우위를 뜻하지 않는다.
- 가능하면 한 cap을 한 threadgroup의 작업으로 두고, 그룹 내 여러 thread가 후보와 점 포함 검사를 분담한다. group 크기·shared memory 수용 정점 수는 실제 자산과 GPU에서 정한다. 여러 그룹이 필요하면 전역 동기화를 별도로 설계한다.
- 각 라운드는 읽기 전용 active ring snapshot, 후보 검사, 안전한 동시 제거 집합 선택, 삼각형 기록, 새 ring 갱신 순서다. 후보 검사 도중 다른 thread가 수정한 prev/next를 섞어 읽지 않는다. 원본 vertex ID의 홀짝만으로 현재 ring의 독립성을 판단하지 않는다.
- 동시 제거 집합은 귀 삼각형/대각선의 충돌과 topology 갱신 충돌이 없음을 보장해야 한다. 순환 경계의 마지막/첫 후보, 중복 후보, 잔여 정점 최소 3개를 검증한다. 논문의 안전성 보장이 임의의 GPU 변형에도 자동 적용된다고 주장하지 않는다.
- 정확성 비교용으로 GPU 단일-thread 순차 ear clipping과 후보 검사만 병렬화하고 한 ear씩 제거하는 경로를 둔다. 여러 ear의 동시 제거는 이 기준 구현과 영역·면적·winding·출력 수를 비교한 뒤 채택한다.
- 작은 잔여 ring은 GPU 안에서 순차 처리하는 안을 비교한다. CPU로 정점 전체를 왕복시키는 fallback을 필수로 하지 않는다. 반복/용량 상한과 진행 실패 status를 두고 무한 shader loop를 만들지 않는다. 순차 전환 기준은 실측하며 논문의 CPU 값을 복사하지 않는다.
- 출력은 고유 slot 또는 scan/compaction으로 충돌을 피하고 남은 마지막 삼각형을 별도로 처리한다. count overflow·퇴화·열린 경계는 잘못된 fan으로 숨기지 않고 명시 실패로 처리한다.
- A/B가 같은 절단 snapshot의 동일 cap 영역을 공유한다면 topology 삼각분할은 한 번 수행하고 반대 winding의 양쪽 인덱스를 만든다. 표면 재질·UV·법선·각 조각의 변형 출처는 별개로 보존한다.

HLSL의 [GroupMemoryBarrierWithGroupSync](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/groupmemorybarrierwithgroupsync)는 그룹 안의 동기화이며 분기마다 일부 thread만 호출하면 동작이 정의되지 않는다. 여러 그룹/dispatch 사이에서는 필요한 [UAV barrier·리소스 상태](https://learn.microsoft.com/en-us/windows/win32/direct3d12/using-resource-barriers-to-synchronize-resource-states-in-direct3d-12)를 별도로 적용한다. 그룹 barrier를 전역 barrier로 가정하지 않는다.

### 검증 및 설계 판단

이 절은 구현 전 조사 시점의 기록이다. 이후 실제 Static GPU 구현·GPU 측정은 [StaticCutImplementation.md](StaticCutImplementation.md)에 추가했다. 문헌 조사만으로는 GPU 가속을 입증하지 않는다. 경계 정점 수별로 순차 GPU / 후보 병렬 / 안전한 다중 ear 제거를 비교한다. 볼록·오목·얇은 영역·긴 나선·CW/CCW·순환 경계·중복/공선 입력을 검증하고, hole은 bridge와 영역 처리가 검증되기 전 별도 미지원으로 분리한다.

측정은 후보 검사 시간, 한 cap 전체 삼각분할 시간, 선분 연결을 포함한 단면 생성 시간, 절단 요청부터 두 결과 게시까지의 시간을 구분한다. GPU timestamp로 dispatch·동기화·scan 비용을 포함하고 readback 대기를 측정에 섞지 않는다. 이 조사로 단일 cap 내부 병렬화의 알고리즘 후보는 찾았지만, 실시간 GPU 가속이나 cap 전체 생성 완료를 입증한 것은 아니다.
