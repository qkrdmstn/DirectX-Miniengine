# MC7 임시 실험 결과 (VC 경로 최적화, HEAD aaa8c4a7 위)

조건: MX450, Release, -debug 0(검증 실행만 -debug 1), TAA off, vsync off, 조합당 1회 실행. 모드 6개 x 3사이클, 전환 후 30프레임 제외, 모드당 창별 200표본. GPU 합 = shadow+depth+opaque+transparent timestamp 합(전체 프레임 아님). MC6 열은 06edbd76 기반 이전 빌드 값이라 같은 모드라도 빌드 차이가 섞인다(예: None-orig HDR 차이 픽셀 수가 달라짐). 결과 CSV 원본은 MC7\main에 있다.

## 최적화 내용 (MC6 대비)

1. 마스크 원천 = VS-1 `m_Bits`(Mode 8). VCCandidate 버퍼, Mode 7 초기화, Mode 0 InterlockedAnd, VCMaskApplyCS 삭제.
2. 게시 때 누적 dispatch가 없다. 저장 의미를 1=숨김으로 뒤집고 Mode 8의 변형인 Mode 9가 `MaskOut = 선택 | 이전 게시 마스크`를 같은 dispatch 안에서 쓴다(워드당 Load 1, Store 1 추가). 마스크는 컴포넌트가 두 장(ping-pong)을 첫 추출에서 한 번만 0으로 만들고, 게시는 `Current` 인덱스만 뒤집는다(GPU 작업, 할당, Create/Retire, PSO 모두 없음). 게시 확정 전에는 쓰기 쪽만 바뀌므로 취소된 제출은 영향이 없다.
3. 추가 인스턴스는 `shared_ptr<VertexMaskStore>`를 공유해 복사가 없다.
4. VC 모드는 제거 삼각형이 있는 section(RenderOverrides[i] 존재)만 마스크 SRV(section 시작 offset을 SRV 주소 offset으로 전달)와 VC PSO를 쓰고 원본 R16 IB를 그대로 읽는다. MC6의 R32 전체 사본 IB 생성도 사라진다.
5. VS는 Load 1회 + shift/and 후 기록이다. discard-any는 숨김=1을 그대로 보간(MC6의 1-m 연산 제거), clip은 0.5-h.
6. Compact/Degenerate/None 모드는 MC6와 같다(Compact = HEAD CP-8).
